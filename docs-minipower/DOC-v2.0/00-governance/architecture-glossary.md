## 1. Thuật ngữ Quản trị Kiến trúc & Tiêu chuẩn Hồ sơ Giải pháp (Architecture Governance)

| Thuật ngữ                                  | Định nghĩa Kỹ thuật                                                       | Ý nghĩa & Vai trò trong Dự án mSMI                                                                                                                                                                                            |
| -------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SAD (DOC-08)**                       | Software Architecture Document (Tài liệu Kiến trúc Giải pháp Phần mềm) | Hồ sơ kiến trúc tổng thể áp dụng mô hình 4+1 Architectural Views (Logical, Process, Development, Physical, Scenarios), mô tả toàn diện 23 Technical Containers, 47 tiến trình PM2 và 8 Core Pipelines.            |
| **ADR (DOC-09)**                       | Architecture Decision Record (Bản ghi Quyết định Kiến trúc)              | Tập hợp các văn bản lưu vết lý do, bối cảnh, phương án lựa chọn và hậu quả kỹ thuật của 7 quyết định thiết kế cốt lõi trong hệ thống (`ADR-001` đến `ADR-007`).                                |
| **NFR (DOC-13)**                       | Non-Functional Requirements (Yêu cầu Phi chức năng)                        | Bộ 25 chỉ số định lượng bắt buộc về chất lượng kỹ thuật: Hiệu năng tải, Tính sẵn sàng HA, Khả năng mở rộng, Bảo mật thông tin và Kịch bản kiểm chứng thực nghiệm (`SC-001` đến `SC-005`). |
| **Technical Container (`CNT-NNN`)**  | Đơn vị thực thi hoặc lưu trữ độc lập cấp hệ điều hành/mạng     | Vỏ bọc kỹ thuật chứa mã nguồn hoặc dịch vụ có thể chạy độc lập, cấp phát tài nguyên riêng (ví dụ: Node.js API Gateway, .NET Worker Mesh, MongoDB, RabbitMQ, MinIO S3). Hệ thống có 23 containers.        |
| **Component (`CMP-NNN`)**            | Thành phần logic nghiệp vụ bên trong container                            | Mô-đun phần mềm, controller, service hoặc engine xử lý chuyên biệt đảm nhiệm một chức năng cụ thể (ví dụ: `HeaderParserEngine`, `XmlVerificationEngine`, `ProxyRotationManager`).                         |
| **Runtime Pipeline (`PIPE-NNN`)**    | Chuỗi tiến trình vận hành nghiệp vụ liên-service                       | Luồng xử lý dữ liệu phối hợp xuyên suốt qua nhiều container qua cơ chế Event-driven hoặc RPC (ví dụ: `PIPE-001` Auto Crawl, `PIPE-003-PDF` Bulk PDF & Fallback).                                                |
| **Integration Contract (`INT-NNN`)** | Hợp đồng giao tiếp tích hợp ngoại vi                                    | Đặc tả kỹ thuật ràng buộc về giao thức, định dạng bản tin, cơ chế xác thực, SLA và fallback khi kết nối với 7 hệ thống bên ngoài (CQT, eTax, 2Captcha, Proxy...).                                         |

## 2. Thuật ngữ Kỹ thuật, Mẫu Thiết kế & Hạ tầng mSMI

| Thuật ngữ / Khái niệm                               | Ý nghĩa Kỹ thuật                                                              | Vai trò & Ứng dụng trong Hệ thống mSMI                                                                                                                                                                                               |
| ------------------------------------------------------- | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Crawl Bot Desktop (`minvoice-plugin`)**       | Ứng dụng Desktop viết bằng C# chạy trên máy client/desktop                 | Kết nối Cổng HĐĐT của Tổng cục Thuế thông qua giao thức SignalR, hỗ trợ giải quyết bài toán vượt rào chặn IP và môi trường mạng doanh nghiệp.                                                                  |
| **SignalR Hub (`signalr-service`)**             | Dịch vụ điều phối kết nối thời gian thực (ASP.NET Core)                  | Quản lý kết nối hai chiều với hàng loạt Bot Desktop qua WebSocket, duy trì trạng thái bot rảnh/bận qua Redis cache key `Bots_Running`.                                                                                     |
| **Crawl ETL Service (`crawl-etl-service`)**     | Worker xử lý trích xuất và điều phối (.NET)                               | Lắng nghe các queue yêu cầu cào hóa đơn từ RabbitMQ, đóng gói `MessageCrawl` và phân phối sang SignalR Hub hoặc Proxy Forwarder.                                                                                        |
| **Proxy Forwarder (`proxy-forwarder-service`)** | Dịch vụ luân phiên HTTP Proxy (.NET 9)                                        | Thực hiện chuyển tiếp request sang Cổng Thuế qua mạng lưới IP xoay vòng. Áp dụng `ADR-007`: dừng failover ngay lập tức khi CQT lỗi 500/503/timeout để chống bão request.                                            |
| **Proxy Request API (`proxy-request-api`)**     | Cổng giao tiếp nội bộ chuẩn hóa kết nối Thuế                             | Nguồn tập trung duy nhất (Single Source of Truth) chịu trách nhiệm ánh xạ và dựng mã thông điệp lỗi CQT (`M401`, `M429`, `M500`, `M503`, `M504`).                                                                |
| **Header Service (`header-service`)**           | Worker xử lý danh sách hóa đơn (.NET 6)                                     | Phân tích cú pháp Excel bảng kê cào về, lọc `ttxly ∈ {5,6,8}`, kiểm soát ngưỡng `RecordLimit=6000`, định tuyến sang 5 hàng đợi độc lập (`auto-daily`, `auto-month`, `auto-year`, `retry`, `manual`). |
| **XML Service (`xml-service`)**                 | Worker xử lý tệp XML (.NET 6)                                                  | Giải mã base64 XML, kiểm tra thẻ `<DSCKS>`, xác thực chữ ký điện tử X.509, bóc tách chi tiết dòng hàng hóa và upload lưu trữ vào MinIO S3.                                                                         |
| **PDF Services (`pdf-services`)**               | Microservice render & lưu trữ PDF (.NET 10)                                     | Nhận queue PDF, kiểm tra magic header `%PDF`, xác định phân vùng bucket MinIO và cập nhật metadata vào MongoDB; chuyển tin lỗi vào Dead-letter queue (DLQ).                                                               |
| **Compare-And-Swap (CAS)**                        | Kỹ thuật kiểm soát đồng thời không khóa (Optimistic Concurrency Control) | Áp dụng tại `consumer_invoice_header` và `consumer_invoice_detail` khi cập nhật MongoDB `invoiceraws`, ngăn chặn ghi đè mất dữ liệu giữa luồng cào tự động và cào thủ công.                                  |
| **Data Repair Engine**                            | Cơ chế tự động bù đắp dữ liệu thiếu                                    | Khi phát hiện chi tiết hóa đơn hoặc XML bị thiếu do đứt đoạn mạng, consumer tự kích hoạt chu trình cào bù (auto data repair) mà không cần người dùng thao tác lại.                                            |
| **Pug HTML-to-PDF Fallback**                      | Cơ chế dựng đồ họa hóa đơn thay thế                                     | Khi nhà cung cấp gốc không xuất file PDF, Worker Thread trong `node_www` sử dụng template Pug (mẫu 1–6) để kết xuất PDF bản thể hiện từ file XML gốc (concurrency giới hạn 2, timeout 120s).                        |
| **PM2 Ecosystem**                                 | Trình quản lý tiến trình Node.js trên server                                | Điều phối 47 ứng dụng tiến trình chạy ngầm (1 web server, 1 satellite proxy, 29 workers cào dữ liệu, 16 consumers RabbitMQ).                                                                                                  |
| **RabbitMQ Exchange & Queues**                    | Message Broker trung tâm                                                         | Sử dụng Direct/Topic Exchange (`crawl-invoice-raw`, `mtax_crawl`) để tách biệt luồng xử lý và đảm bảo tính chịu lỗi, chống tắc nghẽn với Prefetch QoS từ 1 đến 30.                                             |
| **MinIO Multi-Zone Object Storage**               | Hệ thống lưu trữ đối tượng tương thích S3                              | Thay thế việc lưu trực tiếp file nhị phân vào MongoDB, chia vùng theo bucket: `minio-default` (hóa đơn trước tháng 10/2026) và `minio-202610` (từ tháng 10/2026 trở đi).                                          |
| **Hangfire (`batch-job`)**                      | Framework quản lý tác vụ nền định kỳ (.NET)                               | Quản lý lịch quét định kỳ, theo dõi trạng thái job phân tán với storage trên MongoDB và Redis, tối ưu connection pool RabbitMQ dùng chung (`ADR-006`).                                                                |
| **mTax Pipeline**                                 | Hệ thống con quản lý Thuế điện tử                                         | Chạy trên exchange riêng `mtax_crawl` và cơ sở dữ liệu Mongo riêng `mtax`, độc lập hoàn toàn với luồng Hóa đơn điện tử theo tiêu chuẩn cô lập `AG-005`.                                                   |
